# NeoSQLite v1.17.2 Release Notes

## TL;DR

NeoSQLite v1.17.2 is a **correctness and PyMongo API parity release** resolving gaps surfaced during real-world dogfooding (e.g. against blogging platforms like `neo-blogger`). It introduces native SQLite FTS5 BM25 text relevance scoring and sorting in `find()`, PyMongo-compatible multi-field text index creation syntax, fluent chaining methods on `GridOutCursor` (`sort()`, `skip()`, `limit()`, `batch_size()`, `to_list()`), direct `Connection` instantiation for `GridFSBucket`, safe collection counting on GridFS system tables, and expanded unit test coverage reaching **81.18%**. Fully backward compatible.

**Key Highlights:**
1. **FTS5 BM25 Text Relevance Scoring & Sorting** — `find({"$text": {"$search": ...}})` computes true BM25 relevance scores across indexed fields (e.g. `title`, `subtitle`, `body`), supports score projection via `{"score": {"$meta": "textScore"}}`, enables sorting by `[("score", {"$meta": "textScore"})]`, and cleanly prevents internal ranking columns from leaking into returned documents.
2. **MongoDB-Style Multi-Field Text Index Definitions** — `collection.create_index([("field1", "text"), ("field2", "text")])` creates FTS virtual tables across all specified text fields in a single call, matching PyMongo syntax.
3. **Fluent `GridOutCursor` Pagination & Retrieval** — Added `.sort()`, `.skip()`, `.limit()`, `.batch_size()`, and `.to_list()` to `GridOutCursor`, enabling idiomatic cursor chaining on GridFS file searches.
4. **Direct Connection Support in `GridFSBucket`** — `GridFSBucket(conn)` accepts a `neosqlite.Connection` instance directly (automatically unwrapping the underlying SQLite database handle) while retaining backward compatibility with raw database connections (`GridFSBucket(conn.db)`).
5. **Safe Document Counting on GridFS System Collections** — `conn.fs.files.count_documents()` and `conn["fs.files"].count_documents()` now map directly onto relational schema columns (`_id`, `id`, `filename`, `length`, `metadata`, `aliases`) without raising `no such column: data`.
6. **Robust Test Suite & Strict Code Coverage** — Added comprehensive unit tests covering GridFS query compilation, JSON column operators, bulk write duck-typing, and custom SQLite helper functions, bringing overall test coverage to **81.18%** across 3,034 passing tests and achieving **100.0% PyMongo compatibility** across 404 comparison cases against MongoDB 8.2.12.

## Detailed Changes

### Full-Text Search (FTS5)

* **BM25 Text Relevance Score in `find()`:**
  * Implemented `_build_fts_subquery` and `_build_full_fts_query` in `SqlQueryBuilderMixin` leveraging SQLite's native FTS5 `bm25()` auxiliary function.
  * Inverted FTS5 negative BM25 values into positive relevance scores (`-bm25(...) + 100.0`) matching MongoDB textScore expectations.
  * Supported composite scoring across multiple virtual tables, summing relevance scores across distinct indexed columns (such as `title`, `subtitle`, and `body`).
* **Score Projection & Sorting:**
  * Supported projection expression `{"score": {"$meta": "textScore"}}` to expose relevance scores under user-specified keys.
  * Supported sort specifiers matching PyMongo conventions: `[("score", {"$meta": "textScore"})]` or `{"score": {"$meta": "textScore"}}` or `[("$meta", "textScore")]`.
  * Clean projection guarantee: internal tracking fields (`_textScore`) are automatically stripped before output generation.
* **Multi-Field Text Index Syntax:**
  * In `IndexManager.create_index`, recognized lists of `(field, "text")` tuples and automatically initialized FTS5 virtual tables and key mappings for each field.

### GridFS Engine

* **Direct `Connection` Parameter Binding:**
  * Updated `GridFSBucket.__init__` and `GridOutCursor.__init__` to inspect input connections and extract `getattr(db, "db", db)`. Developers can now pass `GridFSBucket(conn)` interchangeably with `GridFSBucket(conn.db)`.
* **Fluent `GridOutCursor` Operations:**
  * Added `sort(key_or_list, direction=1)`: Supports string keys, dictionaries, and list of `(key, direction)` pairs.
  * Added `skip(count)` and `limit(count)`: Applied via SQL `LIMIT` and `OFFSET` clauses directly against `fs_files`.
  * Added `batch_size(size)`: Configures cursor retrieval batch sizes.
  * Added `to_list(length=None)`: Materializes matching files as a list of `GridOut` objects.
  * Added `clone()` and `rewind()`: Supports restarting or duplicating cursor state.
  * Added iterator state guards: Prevents mutating cursor options after iteration has commenced.
* **GridFS Collection Counting:**
  * In `Collection.count_documents` and `estimated_document_count`, routed dotted access for `fs.files` and `fs.chunks` to `_count_documents_as_gridfs()`.
  * Parsed filters against physical table columns (`files_id`, `n`, `length`, `filename`, `_id`, `metadata`) avoiding errors looking for the nonexistent `data` JSON column.

### Code Quality, Typing & Testing

* **Type Safety & Static Analysis:**
  * Resolved all `mypy` type check diagnostics across `index_manager.py`, `cursor.py`, `_sql_query_builder.py`, and `collection/__init__.py`.
  * Achieved 0 type errors across 119 source files under `./scripts/type-check.sh`.
* **Linting & Code Formatting:**
  * Clean run of `./scripts/lint-check-and-fix.sh` (Ruff `I,F` rules) and `./scripts/code-format.sh` (Black line length 80 and trailing whitespace cleanup).
* **Test Coverage:**
  * Added 4 new dedicated test suites:
    * `tests/test_coverage_gridfs_queries.py`: Exhaustive query builder, JSON operators, and cursor method tests.
    * `tests/test_coverage_requests.py`: BulkWrite request model and duck-typing fallback parsing.
    * `tests/test_coverage_connection_helpers.py`: Custom SQLite functions (`regexp_find`, `regexp_find_all`, `regexp_replace`).
    * `tests/test_coverage_type_converters.py`: Multi-field text index creation and `$expr` type conversion tests.
  * Total code coverage increased from 79.74% to **81.18%**, exceeding the 80% coverage threshold.
