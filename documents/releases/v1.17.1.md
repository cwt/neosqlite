# NeoSQLite v1.17.1 Release Notes

## TL;DR

NeoSQLite v1.17.1 is a **correctness and API parity release**. It resolves cross-tier serialization mismatches in the Tier-2 (temporary table) aggregation engine, expands NX-27017 MongoDB wire protocol server compatibility to **100.0%** across the PyMongo differential test suite (resolving TTL index declarations, PyMongo 4.x GridFS query operators, and `dropDatabase` support), and eliminates the remaining `ResourceWarning` in the test suite.

**Key Highlights:**
1. **Tier-2 Aggregation Serialization Parity** — Object elements sorted via `$sortArray` now return as structured JSON dictionaries rather than JSON strings; `$unwind` correctly preserves object scalar types without stringification or Python `repr` formatting; and `$project` strips missing fields via `json_remove` to match MongoDB omission semantics.
2. **100% NX-27017 API Compatibility** — Resolved all remaining failures in the PyMongo differential benchmark (`./scripts/run-api-nx-27017.sh`), bringing compatibility to **100.0%** (378 passed, 17 skipped, 0 failed).
3. **TTL Index Expiry & Directional Name Resolution** — `createIndexes` and `listIndexes` now capture and expose `expireAfterSeconds` and `unique` metadata. `IndexManager.drop_index()` resolves PyMongo directional index names (e.g. `field_1`, `field_-1`) against SQLite indexes and cleans up associated TTL metadata.
4. **PyMongo 4.x GridFS Operator Handling** — Unwrapped `{"$eq": ...}` operand dicts on `_id` and `files_id`, supported chunk range queries on `n` (`$gte`, `$gt`, etc.), and returned the canonical file `ObjectId` instead of internal integer table IDs.
5. **Zero Test Warnings & Clean Resources** — Fixed an unclosed `sqlite3.Connection` handle in WAL migration unit tests, ensuring the entire test suite runs with 0 warnings while exceeding 80% coverage.

## Detailed Changes

### Aggregation Engine (Tier-2 Temporary Tables)

* **JSON Dictionary Formatting in SQL Generation:** Replaced Python `str(dict)` representations (which generated invalid JSON like `"{'n': 1}"`) with standard JSON formatting (`json.dumps()`) in Tier-2 aggregation operators.
* **`$sortArray` Object Preservation:** Parsed JSON string items back into dictionaries after sorting, ensuring arrays of subdocuments retain their native object types across all evaluation tiers.
* **`$unwind` on Object Scalars:** Wrapped object scalar unwinds with `json()` within `json_array()` expressions so non-array object payloads retain object types rather than being treated as plain strings.
* **`$project` Missing Field Omission:** Enhanced Tier-2 `$project` using SQLite's `json_remove()` to strip projected fields evaluating to `NULL`/missing, aligning Tier-2 results with Tier-1 and PyMongo specification.

### NX-27017 MongoDB Wire Protocol Server

* **`dropDatabase` Command Support:** Added explicit handlers for `dropDatabase` and `dropdatabase` commands, evicting the database instance from internal caches and returning `{"dropped": db_name, "ok": 1}`.
* **TTL Index Declaration & Listing:**
  * Captured `expireAfterSeconds` in `createIndexes` requests and passed it directly to `coll.create_index()`.
  * Queried `coll.index_information()` in `_handle_list_indexes` to populate `firstBatch` documents with `expireAfterSeconds` and `unique` flags.
* **GridFS Filter Normalization & Chunk Queries:**
  * Unwrapped `{"$eq": ...}` filters in `GridOutCursor` parameter bindings to prevent `sqlite3.ProgrammingError: type 'dict' is not supported`.
  * Supported `$in` operator with parameterized SQL placeholders in `GridOutCursor._build_query()`.
  * In `GridFSAdapter.handle_chunks_find()`, supported range queries on `n` (`$gte`, `$gt`, `$lte`, `$lt`, `$eq`) and mapped `files_id` to the file's original `ObjectId` rather than the internal SQLite row ID.
  * Unwrapped `{"$eq": ...}` in `_handle_gridfs_delete` and `_convert_objectid`.

### Collection and Index Management

* **Directional Index Suffix Resolution:** `IndexManager.drop_index()` inspects `sqlite_master` candidate indexes to resolve PyMongo-style names ending in `_1` or `_-1` (e.g. `date_1`) to the internal SQLite index (e.g. `idx_coll_date`), ensuring proper index drop and purge of stored TTL options.

### Testing and Reliability

* **Resource Cleanup in WAL Migration:** Added explicit `conn.close()` to `test_migrate_with_uncheckpointed_wal` in `tests/test_migration.py`, eliminating Python 3.14 GC `ResourceWarning` unclosed database warnings.
* **Cross-Tier Audit Tests:** Added regression tests in `tests/test_audit_fixes.py` verifying that `$sortArray` object elements, `$unwind`, and missing field projection match identically across Tier 1, Tier 2, and Tier 3 (Python fallback).

```bash

pip install "neosqlite[nx27017]==1.17.1"
```

## Migration Guide

### Upgrading from v1.17.0 to v1.17.1

1. **Seamless Drop-In Replacement:** Fully backward compatible; no database schema or storage format migrations required.
2. **Aggregation Results:** Pipelines utilizing Tier-2 aggregation with `$sortArray` over object elements now return dict items instead of serialized JSON strings.
3. **NX-27017 Compatibility:** Applications interacting with NX-27017 through PyMongo 4.x for GridFS operations or TTL indexes now operate without errors or schema mismatches.
