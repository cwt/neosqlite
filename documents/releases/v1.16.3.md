# NeoSQLite v1.16.3 Release Notes

## TL;DR

NeoSQLite v1.16.3 is a **correctness patch**. Since v1.16.0, updates deliberately store documents as JSONB (`jsonb_set`, "gradual migration to JSONB storage"), but `DateTimeQueryProcessor` still selected the raw `data` column and deserialized it as UTF-8 text. On SQLite builds with JSONB support, every updated row therefore failed to decode: datetime-filtered queries logged `Skipping corrupted document` and returned stubs containing only `_id` and `__neosqlite_corrupted__`, silently dropping all document fields. The processor now selects `json_data_column()` like every other read path, so JSONB blobs are converted with `json(data)` before decoding.

**Key Highlights:**
1. **Datetime Queries Return Full Documents** — the SQL tier and both temporary-table tier reads (base table and filtered result) convert the `data` column.
2. **No More "Skipping corrupted document"** — updated rows decode again; malformed rows keep hitting the existing `_load_with_stored_id` guard instead of failing the query.
3. **Read-Path Only, Fully Backward Compatible** — no storage format, schema, or API change; no data migration required.

---

## Detailed Changes

### Core `neosqlite` Engine

* **Datetime query processor (`neosqlite/collection/datetime_query_processor.py`):**
  Replaced `SELECT id, _id, data ...` with `SELECT id, _id, {json_data_column(self.jsonb.jsonb_supported)} as data ...` in `_process_with_sql_tier`, and in `_process_with_temp_table_tier` for both the base temp table creation and the filtered-result read. `json_data_column()` wraps JSONB blobs with `json()` and normalizes valid JSON text, matching the cursor, CRUD, aggregation, and group read paths. `_load_with_stored_id` receives text again and the document decode succeeds.

### Tests

* **Regression tests (`tests/test_datetime_query_processor.py`):**
  Added `test_datetime_query_returns_documents_updated_with_jsonb` (public `find()` path) and `test_temp_table_tier_returns_documents_updated_with_jsonb` (temporary-table tier called directly). Both insert a document, update it with `$set` (which is what stores JSONB), then run a `$lte` datetime query and assert the full document is returned (`name`/`status` present, no `__neosqlite_corrupted__`). Before the fix these queries returned `{'_id', '__neosqlite_corrupted__'}`.

## Migration Guide

### Upgrading from v1.16.2 to v1.16.3

1. **Seamless Drop-In Replacement:** No APIs or signatures changed.
2. **Behavior Fix — Datetime Filters:** queries combining a datetime operator (`$gt`/`$gte`/`$lt`/`$lte`) with other fields now return matching documents with all fields, instead of `{_id, __neosqlite_corrupted__}` stubs. Code that worked around the stubs (e.g. re-fetching by `_id`) can drop that workaround.
3. **No Data Migration:** the storage format is unchanged; only the read SELECT was fixed.
