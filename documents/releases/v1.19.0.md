# NeoSQLite v1.19.0 Release Notes

## TL;DR

NeoSQLite v1.19.0 is a **feature and correctness release** rolling up every change after the `v1.18.1` tag (revisions 1038–1137). It delivers the 28 audited issue fixes (#183–#210), new aggregation/query capabilities, persistent collection validators, pluggable out-of-process JavaScript engines, a hardened NX‑27017 wire server, and a stricter differential test harness.

The Python floor is unchanged: **Python 3.12+** (`>=3.12,<3.16`).

## New Features

- **`$meta` across all tiers** — SQL compilation for `textScore`, scope validation, `_textScore` stripping, and PyMongo differential coverage.
- **BSON-aware `_id` ranges** — `$gt/$gte/$lt/$lte` on `_id` compile to SQL with per-BSON-type guards instead of Python evaluation.
- **Tier‑2 hybrid stage evaluation** — a single declining stage runs in Python while the rest of the pipeline stays in Tier 2.
- **`$indexStats`** — Tier‑3 metadata stage with MongoDB-shaped output and first-stage-only validation.
- **JavaScript engines** — pluggable, process-isolated backends with `jsbox` preferred over a patched Node.js; `$function` and `$where` run in a sandbox with scrubbed environment and bounded resources.
- **Stage aliases** — `$set` and `$sortByCount` normalized for all tiers, including `$facet` and `$lookup` sub-pipelines.
- **Persistent collection validators** — `$jsonSchema` metadata now survives close/reopen and is enforced on inserts/updates/replacements through both the direct API and NX‑27017.
- **Benchmark and comparison tooling** — large-collection benchmark categories, an Edge Case Parity differential module, and gates that fail on comparison exceptions, missing results, or excessive skips.

## Correctness Fixes Since v1.18.1

The `Fix #NNN` series (#183–#210) was audited against each GitHub issue, the exact diff, and MongoDB differential behavior:

- **Transactions & sessions** (#183, #206) — rollback on close, ended-session guards, per-transaction connections, per-database locking, DoS bounds, daemon/PID safety.
- **SQL construction** (#192), **JS worker hardening** (#188), **migration** (#185), **indexing/FTS5** (#189), **TTL & collection lifecycle** (#184), **GridFS** (#191), **ChangeStream** (#186), **query translator** (#193), **cursors** (#190), **updates/bulk writes** (#194), **schema validation** (#195), **optimizer** (#196), **translation cache** (#197), **bucket/group** (#198), **document reshaping** (#199), **advanced stages** (#200), **expression evaluators** (#201, #202), **BSON value types** (#203), **wire protocol** (#204), **command handler** (#205), **dead code** (#207), **consolidation** (#208), **performance** (#209), **docs/scripts** (#210).

Post-audit corrections verified against real MongoDB and NX‑27017 runs:

- `$lookup` `let` substitution is context-aware; `$literal` operands stay opaque.
- `$graphLookup` with ObjectId keys works on JSONB-capable SQLite.
- `$$ROOT` is correct after `$count` and for `$densify` synthesized rows.
- Ambiguous dotted numeric paths use the Python tier deliberately instead of silently no-oping in SQL.
- `_id_` index hints resolve correctly; index directions are validated.
- `$bucketAuto` now uses MongoDB's exclusive upper-bound semantics in all three tiers.
- Numeric array indexes (`arr.1`) work in the Python query matcher.
- ChangeStream filters are BSON-strict; `$replaceOne` with `find: None` is tier-consistent.
- Closed-cursor `rewind()` raises `InvalidOperation`; stale SQLite cursor cleanup is silent.
- FTS/shadow table column caches are invalidated on drop/rename; JSONB containment binds values with the correct type.

## Behavior Changes and Compatibility Notes

- **`$bucketAuto` boundaries changed** — non-final buckets report the next bucket's first value as `max`, matching MongoDB.
- **`Cursor.rewind()` on a closed cursor now raises `InvalidOperation`** (PyMongo-compatible) instead of silently resurrecting the cursor.
- **Daemon PID identity is strict** — a process is only recognized as NX‑27017 by its executable/module, not by a substring anywhere in its command line.
- **Numeric dotted paths use Tier 3** — `a.1` is ambiguous (array index vs literal document key), so SQL declines rather than guessing.
- **NX‑27017 `createCollection` forwards `validator`** — validators are now enforced over the wire protocol.
- **New internal table `_neosqlite_validators`** holds persisted validator metadata; it is excluded from `list_collection_names()`.
- **JS engine selection prefers `jsbox`** when available; set `NEOSQLITE_JS_ENGINE=node` to force Node.js.
- **Performance tradeoff** — correctness fixes add ~20–400% to some benchmark categories; overall speedup is ~3.4x versus 4.5x in the pre-audit report. The audit round itself changed total benchmark time by only ~1.5%.

## Verification

- **3446 unit tests** pass; `nx-27017` suite: **231 passed, 1 skipped**.
- **`scripts/run-api-comparison.sh`** (podman/MongoDB): 452 checks, 433 passed, 19 skipped, **0 failed, 100% compatible**.
- **`scripts/run-api-nx-27017.sh`**: 452 checks, 436 passed, 16 skipped, **0 failed, 100% compatible**.
- `type-check.sh`, `lint-check-and-fix.sh`, and `code-format.sh` are clean.
- Tier-routing tests confirm fixed operations still execute in Tier 1/2; only deliberately ambiguous numeric paths use Tier 3.

## Upgrade Notes

No runtime or packaging floor changes. Applications that called `rewind()` on a closed cursor or relied on the old `$bucketAuto` boundary values should review those call sites. Existing databases gain the `_neosqlite_validators` metadata table lazily when a validator is first created.
