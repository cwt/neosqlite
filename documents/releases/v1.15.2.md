# NeoSQLite v1.15.2 Release Notes

## TL;DR

NeoSQLite v1.15.2 is a **focused correctness, stability, and documentation release**. It resolves SQL-tier bugs in temporary table `$lookup` and negative `$slice` array updates, rolls in 10 stability and concurrency fixes for the NX-27017 wire protocol server (v0.6.3), updates dependencies (PyMongo `^4.18.0`), and documents container testing with `mongo:8.2.12`. All core fixes are backward compatible.

**Key Highlights:**
1. **`$lookup` Hash Table Malformed JSON Fix** — Tier-2 temporary table hash index creation on string foreign fields no longer raises SQLite `malformed JSON` errors or forces row-by-row fallback.
2. **Negative `$slice` Update Ordering** — `$push` array updates with negative `$slice` modifiers now reliably preserve original element ordering in the SQL tier without relying on invalid subquery rowids.
3. **NX-27017 Wire Protocol Server Hardened (v0.6.3)** — Serialized access to shared SQLite connection, plugged change-stream listener memory leak, preserved Decimal precision via BSON Decimal128, and returned empty cursors on uninitialized collections.
4. **Knowledge Base Migration to OKF v0.2** — Migrated documentation to Google Open Knowledge Format v0.2 and retired the legacy root `CHANGELOG.md` in favor of modular per-version release notes.
5. **Pinned Test Image (`mongo:8.2.12`)** — Pinned differential API test container to `mongo:8.2.12` to ensure stability on Linux kernels $\ge$ 6.19 while verifying MongoDB 8.0+ operators like `$sigmoid`.

## Correctness Transparency Note

In keeping with our commitment to absolute honesty and transparency with users, this section explains the two SQL-tier bugs fixed in core NeoSQLite in this release: the use cases that triggered them, their technical root causes, their real-world impact, and how to verify or remediate existing databases if you executed these operations on pre-v1.15.2 versions.

### 1. `$lookup` Hash Table Creation on String Foreign Fields

* **The Triggering Use Case:**
  Running an aggregation pipeline with a `$lookup` stage where `foreignField` points to a string field (e.g., `foreignField: "parent_post"` containing string IDs like `"p1"` rather than BSON ObjectIds), combined with any subsequent stage that requires Tier-2 temporary table execution (such as an `$addFields` stage containing `$filter` with the aggregation variable `$$c`).
* **The Nature of the Bug:**
  In `neosqlite/collection/temporary_table_aggregation/utils.py`, the helper `_generate_field_extract_sql()` generates SQL to extract join keys and inspect them for NeoSQLite serialized ObjectId markers (`{"__neosqlite_objectid__": true, "id": "..."}`).
  Previously, the generated SQL tested:
  ```sql
  WHEN json_extract(base_extract, '$.__neosqlite_objectid__') = 1 THEN ...
  ```
  where `base_extract` had already extracted the scalar text string via `json_extract(data, '$.foreignField')`. When `foreignField` was a plain string (e.g., `"p1"`), SQLite passed that raw string back into `json_extract("p1", '$.__neosqlite_objectid__')`. Because raw text is not valid JSON, SQLite aborted the statement with:
  ```text
  malformed JSON
  ```
* **Real-World Impact:**
  NeoSQLite's tiered fallback caught the SQLite error and fell back to Tier 3 (Python evaluation / row-by-row join).
  * **Data Integrity:** **Zero impact.** Your database data was never modified or corrupted; this was strictly an in-memory aggregation query issue.
  * **Query Results:** Correct joined results were returned via the Python fallback tier, but at the cost of warning log noise and degraded aggregation throughput (falling back from high-speed SQL temporary table joins to row-by-row evaluation).
* **How to Correct It if You Used Pre-v1.15.2:**
  * No database migrations or data cleanup are needed.
  * If you implemented application-level workarounds (such as pre-converting string foreign keys to ObjectIds or splitting pipelines into separate queries), you can safely remove them. Upgrading to v1.15.2 allows Tier 2 to execute cleanly in SQLite.

### 2. Negative `$slice` Ordering in `$push` Updates

* **The Triggering Use Case:**
  Updating documents using `$push` with a negative `$slice` modifier (e.g., `{"$push": {"activity_log": {"$each": [new_entry], "$slice": -5}}}`) to append new entries while capping the array to its latest $N$ elements in original chronological order.
* **The Nature of the Bug:**
  In `neosqlite/collection/query_helper/_sql_updates.py`, the SQL update builder implemented negative slicing by scanning the combined existing and newly pushed elements in reverse order (`ORDER BY blk DESC, ord DESC LIMIT N`) and then attempting to re-sort them ascending with:
  ```sql
  SELECT value FROM (reversed_scan) ORDER BY rowid
  ```
  However, in SQLite, derived subqueries created via `UNION ALL` **do not have a `rowid` pseudo-column**. Depending on the SQLite version and the query planner's materialization path:
  1. SQLite raised a query compilation error, which caused NeoSQLite to fall back to the Tier-3 Python update evaluator (which preserved the exact array order correctly), **OR**
  2. SQLite assigned arbitrary rowid values to the materialized rows, resulting in non-deterministic or reverse element ordering stored into the array.
* **Real-World Impact:**
  If your SQLite engine fell back to Python, array ordering was preserved correctly. However, if SQLite executed the subquery ordering arbitrarily, array fields updated with negative `$slice` may have had their capped elements stored out of order.
* **How to Correct It if You Used Pre-v1.15.2:**
  * **Data Audit:** If you executed `$push` updates with negative `$slice` on versions prior to v1.15.2, inspect the affected array fields in your documents to verify whether elements maintain their expected order.
  * **Remediation Script:** If elements are out of order, you can restore them with a one-time script:
    ```python
    import neosqlite

    with neosqlite.Connection("your_database.db") as conn:
        coll = conn.your_collection
        for doc in coll.find({"activity_log": {"$exists": True}}):
            arr = doc.get("activity_log", [])
            # Re-sort using your item's timestamp or ordering key
            sorted_arr = sorted(arr, key=lambda item: item.get("timestamp", 0))
            if arr != sorted_arr:
                coll.update_one({"_id": doc["_id"]}, {"$set": {"activity_log": sorted_arr}})
    ```
  * In v1.15.2, the ordering keys `blk` and `ord` are explicitly projected through the derived subquery (`ORDER BY blk ASC, ord ASC`), guaranteeing strictly deterministic ordering directly in SQL.

## Detailed Changes

### Core `neosqlite` Engine

* **Fix `$lookup` Hash Table Key Extraction:**
  Changed `_generate_field_extract_sql()` in `temporary_table_aggregation/utils.py` to extract the ObjectId sentinel directly from the root JSON column (`json_extract(data, '$.field.__neosqlite_objectid__')`), returning `NULL` cleanly when the field is a string rather than throwing `malformed JSON`.
* **Fix Negative `$slice` Update Subquery:**
  Carried `blk` and `ord` ordering columns through the subquery projection in `_sql_updates.py` and sorted by `blk ASC, ord ASC`, avoiding reliance on non-existent subquery `rowid` attributes.

### NX-27017 Wire Protocol Server (v0.6.3)

Ten hardening and stability bug fixes were rolled into the optional wire protocol server subpackage:
1. **Shared Connection Concurrency:** Serialized thread access to the shared SQLite connection to prevent SQLite locking collisions during concurrent client operations.
2. **Collection Table Recreation on Insert:** Fixed a cache inconsistency where re-inserting into a dropped collection failed to recreate the backing SQLite table.
3. **Duplicate Collection Creation:** Avoided redundant `create()` calls when inserting into an already existing collection.
4. **`serverStatus` Memory Accounting:** Corrected `ru_maxrss` unit handling between Linux (KiB) and macOS (bytes).
5. **`listDatabases` Size Calculation:** Prevented double-counting SQLite database sizes caused by summing main database and WAL/SHM auxiliary files.
6. **Decimal128 Precision:** Preserved `decimal.Decimal` precision via BSON Decimal128 encoding instead of converting to floating-point numbers.
7. **Session Cleanup:** Fixed `endSessions` command failing to clean up raw-byte UUID session identifiers.
8. **`OP_REPLY` Opcode:** Ensured `build_reply` emits standard `OP_REPLY` (opcode 1) for legacy wire protocol clients.
9. **Empty Collection Cursor:** Querying a non-existent collection now returns an empty cursor rather than raising an internal exception.
10. **Change-Stream Listener Leak:** Cleaned up registered change-stream listeners upon client disconnection to avoid memory growth over extended server uptimes.

### Documentation & Build

* **OKF v0.2 Knowledge Base:** Migrated all documentation under `documents/` to Google Open Knowledge Format (OKF) v0.2 specification, with structured YAML frontmatter and kebab-case file paths.
* **Retired `CHANGELOG.md`:** Consolidated release tracking into `documents/releases/` with an interactive directory index (`documents/releases/index.md`).
* **Pinned `mongo:8.2.12` Test Image:** Configured test and benchmark runners (`run-api-comparison.sh` and `run-api-benchmark.sh`) to use `mongo:8.2.12`, providing full MongoDB 8.0+ operator verification while running cleanly on Linux kernels $\ge$ 6.19.
* **Dependency Updates:** Updated PyMongo to `^4.18.0` and removed obsolete SourceHut repository mirrors from package configuration.

## Migration Guide

### Upgrading from v1.15.1 to v1.15.2

1. **Seamless Drop-In Replacement:** No public APIs or function signatures were changed. Upgrading requires zero changes to standard application code.
2. **Aggregations:** Tier-2 `$lookup` queries using string foreign keys will now execute significantly faster in the SQL tier without emitting `malformed JSON` warnings.
3. **Data Verification Checklist:**
   * If your application uses `$push` with negative `$slice` modifiers, run the check outlined in the [Correctness Transparency Note](#2-negative-slice-ordering-in-push-updates) to verify that array element ordering meets expectations.
   * If you run the standalone `nx-27017` daemon, restart the service after updating to ensure the connection serializer and memory leak fixes take effect.
