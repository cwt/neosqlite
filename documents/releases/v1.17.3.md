# NeoSQLite v1.17.3 Release Notes

## TL;DR

NeoSQLite v1.17.3 is a **major correctness, MongoDB API parity, and runtime compatibility release**. Surfaced through differential fuzzing and comprehensive comparison testing against MongoDB 8.x, this release resolves critical semantic differences in query evaluation: `{"$ne": null}` now strictly excludes both missing and explicit `null` fields; `{"$exists": true}` accurately matches present-but-null fields; comparison operators (`$gt`, `$gte`, `$lt`, `$lte`) on array fields now implement existential matching (matching if *any* element satisfies the condition); and `$expr` comparison operators enforce MongoDB's canonical BSON type ordering (`missing < null < numbers < strings < objects < arrays < bools`).

Additionally, this release enhances the **NX-27017 MongoDB Wire Protocol Server** by routing GridFS aggregation pipelines to the adapter (enabling PyMongo's `count_documents()` on `fs.files` and `fs.chunks`), supporting dotted sort keys, and fixing sort/skip execution order. Finally, v1.17.3 introduces official support for **Python 3.15** (`^3.10, <3.16`), upgrading optional dependencies (such as `uvloop` `^0.23.0` with native `cp315` wheels and `sphinx` `<9.3.0`) and verifying all 3,034 unit tests under Python 3.15.2 with **80.78%** line coverage. Fully backward compatible.

**Key Highlights:**
1. **MongoDB Semantic Parity for `$ne: null` & `$exists`** — `{"$ne": null}` now excludes both missing fields and fields explicitly set to `null` across all execution tiers (Python, SQL CTEs, aggregation `$match`, unified SQL translator, and ChangeStreams). `{"$exists": true}` correctly recognizes present-but-null values via SQLite `json_type()`.
2. **Existential Array Comparisons** — Relational comparisons (`$gt`, `$gte`, `$lt`, `$lte`) against array fields now evaluate with existential semantics—matching documents where any array member satisfies the comparison. Scalar type guards prevent array values from false-matching via text comparisons, while `$elemMatch` inner clauses preserve strict scalar scoping.
3. **Cross-Type Query Operators & Strict `$size`** — SQL generation paths for `$ne`, `$in`, and `$nin` now include BSON type guards via `json_each.type`. The `$size` operator strictly requires `json_type = 'array'`, preventing non-arrays from matching. `$eq` natively handles array containment in SQL paths.
4. **`$expr` BSON Type Ordering & Decimal Support** — Implemented canonical BSON type ranking (`missing (0) < null (1) < numbers/Decimal (2) < string (3) < object (4) < array (5) < bool (9)`) in `$expr` evaluations. Ordering comparisons involving `null` are safely routed to authoritative Python fallback.
5. **NX-27017 GridFS Aggregation & Cursor Sorting** — Routed `aggregate` commands on `fs.files` and `fs.chunks` to the GridFS adapter, allowing PyMongo's `count_documents()` to work over the wire protocol. Added support for dotted sort keys (e.g. `metadata.order`), fixed missing-vs-present sort partitioning, and corrected skip-after-sort sequencing.
6. **Official Python 3.15 Compatibility** — Expanded runtime specifications to `^3.10, <3.16`. Upgraded `uvloop` to `^0.23.0` (with pre-built CPython 3.15 wheels) and `sphinx` to `<9.3.0`. Released `nx-27017` v0.8.3 with `neosqlite = "^1.17.3"` binding.
7. **Verified Quality & Test Pass** — All 3,034 unit tests pass on Python 3.15.2 with **80.78%** statement coverage, along with 100% pass rate across 180 NX-27017 wire protocol tests.

## Detailed Changes

### MongoDB Semantic Parity & Query Operator Hardening

* **`$ne: null` and `$exists` Semantics:**
  * **Excluding Missing and Null Fields:** In MongoDB, `{"field": {"$ne": null}}` matches only documents where `field` exists and its value is not `null`. Previously, NeoSQLite's SQL translation and Python filters treated missing fields as satisfying `$ne: null`. This has been corrected across:
    * `neosqlite/collection/query_helper/_sql_query_builder.py`: Emits `json_type(data, path) IS NOT NULL AND json_type(data, path) != 'null'` (or `{id_col} IS NOT NULL` for `_id`).
    * `neosqlite/collection/sql_translator_unified.py`: Generates type-aware SQL clauses for `$ne: null`.
    * `neosqlite/collection/_stage_builders.py`: Updated pipeline `$match` translation.
    * `neosqlite/query_operators.py`: Updated in-memory Python fallback evaluation.
    * `neosqlite/changestream.py`: Updated trigger and change-stream event filtering.
  * **Present-But-Null `$exists` Detection:** `{"$exists": true}` now translates to `json_type(data, path) IS NOT NULL`, correctly matching documents where the field exists with value `null`. `{"$exists": false}` translates to `json_type(data, path) IS NULL`, matching only absent fields.
* **Existential Array Comparisons (`$gt`, `$gte`, `$lt`, `$lte`):**
  * Updated query builders to evaluate comparisons against array fields existentially: if any element of an array satisfies the operator, the document matches.
  * Added `allow_array_existential` parameter to `_build_operator_clause()`.
  * Guarded scalar comparisons to prevent JSON arrays from accidentally matching scalar comparisons via SQLite text comparisons.
  * Preserved scalar-only semantics for inner operators inside `$elemMatch`.
* **Cross-Type `$ne`, `$in`, `$nin`, and Array Containment:**
  * **Type-Restricted `$ne`:** `$ne` comparisons in SQL now check `json_type`, ensuring values of different types are not considered equal.
  * **Type-Guarded `$in` / `$nin`:** When generating `NOT EXISTS (SELECT 1 FROM json_each(...) ...)` clauses, added `json_each.type IN (...)` guards to prevent cross-type false matches.
  * **`$eq` Array Containment:** Added native SQL CTE handling for array containment when querying with `$eq`, aligning with MongoDB's polymorphic equality behavior.
* **Strict `$size` Array Validation:**
  * `$size` now requires `json_type(data, path) = 'array' AND json_array_length(...) = ?` and guards against boolean values, preventing objects or non-arrays from incorrectly matching size queries.
* **Comparison Operators with `None`:**
  * Comparisons with `None` strictly adhere to MongoDB type-restricted semantics:
    * `$gt: None` and `$lt: None` always return `False`.
    * `$gte: None` and `$lte: None` match only null or missing fields.
  * Preserved explicit `null` values in `_iter_leaf_values()`, fixing `$or` and `$and` branch evaluations involving null equality.

### Aggregation & `$expr` BSON Type Ordering

* **Canonical BSON Type Ranking in `$expr`:**
  * Implemented MongoDB BSON type rank order for relational comparisons in `neosqlite/collection/expr_evaluator/python_evaluators/core.py`:
    $$\text{missing (0)} < \text{null (1)} < \text{numbers / Decimal (2)} < \text{string (3)} < \text{object (4)} < \text{array (5)} < \text{boolean (9)}$$
  * When operands have differing type ranks, ordering comparisons (`$gt`, `$gte`, `$lt`, `$lte`) resolve by type rank rather than raising type errors.
  * Added `decimal.Decimal` support to numeric type ranking.
* **SQL Fallback for Null Ordering Comparisons:**
  * In `neosqlite/collection/expr_evaluator/sql_converters/comparison.py`, relational comparisons involving `null` operands are forced to fall back to the Python evaluation tier to ensure exact BSON type ordering correctness.

### NX-27017 Wire Protocol Server Enhancements

* **GridFS Aggregation Support:**
  * Implemented `_handle_gridfs_aggregate()` in `packages/nx_27017/src/nx_27017/handler.py` to route `aggregate` commands on GridFS collections (`fs.files`, `fs.chunks`) through the GridFS adapter.
  * Added full support for `$match`, `$sort`, `$skip`, `$limit`, and `$group` with `$sum` count pipelines, enabling PyMongo's `count_documents()` to operate seamlessly over the wire protocol.
* **Dotted Sort Keys & Sort Order in GridFS `find`:**
  * Supported dotted sort paths (e.g. `metadata.upload_date` or `metadata.order`) when sorting GridFS files.
  * Partitioned documents with missing sort keys according to MongoDB conventions (missing values sort first in ascending, last in descending).
  * Fixed execution sequencing so `skip` is applied *after* sorting.
* **Empty `files_id` Filter in Chunks Handler:**
  * Handled empty or missing `files_id` filters in `handle_chunks_find()`, allowing full chunk collection counts and queries.
* **API Comparison Runner Tuning:**
  * Updated `examples/api_comparison/runner.py` to skip unsupported wire-protocol edge cases when benchmarking against the NX-27017 backend.

### Python 3.15 Compatibility & Tooling Modernization

* **Python Version Specification (`^3.10, <3.16`):**
  * Updated Python version constraints in `pyproject.toml` and `packages/nx_27017/pyproject.toml` from `^3.10, <3.15` to `^3.10, <3.16`.
  * Verified full backward compatibility across Python 3.10, 3.11, 3.12, 3.13, 3.14, and 3.15.
* **Upgraded Optional Dependencies:**
  * Upgraded `uvloop` to `^0.23.0` to provide pre-compiled CPython 3.15 (`cp315`/`cp315t`) binary wheels.
  * Updated `sphinx` constraint for Python >=3.12 to `>=9.1.0,<9.3.0`.
* **Package Alignment:**
  * Bumped `nx-27017` to version `0.8.3` with `neosqlite = "^1.17.3"` dependency.
  * Regenerated `poetry.lock` with Python 3.15 dependency hashes and wheel metadata.
