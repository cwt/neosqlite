# NeoSQLite v1.16.2 Release Notes

## TL;DR

NeoSQLite v1.16.2 is a **correctness patch**. `GridOutCursor` no longer silently drops dotted `metadata.*` filters (e.g. `bucket.find({"metadata.url": ...})` previously returned the whole bucket — including documents like `{"size": None}` for a `{"metadata.size": 720}` query). Dotted `metadata.*`/`aliases.*` filters are now translated to SQLite `json_extract`/`json_type`/`json_each` predicates with MongoDB semantics for equality and `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$in`, `$nin`, `$regex` (+`$options`), `$exists`, `$size`, and `$all`, plus top-level `$and`/`$or`/`$nor`. Unknown fields/operators now match nothing (`1=0`) instead of everything. `conn.fs.chunks.find()` now queries the chunks table directly instead of returning files. Fully backward compatible.

**Key Highlights:**
1. **Dotted Metadata Filters Fixed** — `{"metadata.size": 720}` and the documented `bucket.find({"metadata.url": ...})` pattern filter correctly via `json_extract` (numeric path segments become `[n]` indices; `null` matches null-or-missing).
2. **No More Silent Whole-Bucket Matches** — unknown fields, dotted paths on scalar columns, and unsupported operators yield `1=0`; `$nor` is NULL-safe (`IS NOT TRUE`).
3. **`fs.chunks.find()` Unblocked** — chunks queries return real chunk dicts (`_id`, `files_id`, `n`, `data`) instead of vacuously passing via whole-bucket files.

## Detailed Changes

### Core `neosqlite` Engine

* **Dotted GridFS filters (`neosqlite/gridfs/grid_file.py`):**
  Added `_mongo_dot_subpath_to_json_path` (numeric segments as array indices, e.g. `tags.0` -> `$.tags[0]`), `_append_json_column_equality` (scalar equality plus array-contains via `json_type = 'array' AND EXISTS (json_each ...)`), and `_append_json_column_operators` covering `$eq`, `$ne` (NULL-safe, array-aware), range operators, `$in`/`$nin` (null-aware, array-aware), `$regex` with `$options: "i"`, `$exists` via `json_type`, `$size` via `json_array_length`, and `$all`. `GridOutCursor` routes `metadata.*`/`aliases.*` through these builders, supports recursive `$and`/`$or`/`$nor`, accepts `contentType` as an alias of `content_type`, and emits `1=0` for anything unrecognized.
* **Chunks delegation (`neosqlite/collection/__init__.py`):**
  `_find_as_gridfs` now detects `_chunks` collections and queries the chunks table directly (`_find_chunks_direct` with `files_id`/`n`/`_id` equality and comparison operators), returning chunk dicts. Previously `fs.chunks.find({"files_id": 1})` delegated to `GridFSBucket.find` (files table) and only passed because unknown filters returned the whole bucket.
* **Type annotation (`neosqlite/gridfs/grid_file.py`):**
  Annotated `GridOutCursor` `params: list[Any]`, fixing the single `mypy` error (`./scripts/type-check.sh` green on 119 files).

### Tests

* **Manual verification (no new test files):**
  equality/`$ne`/`$gt`/`$in`/`$nin`/`$exists`/`$regex`/`$options`, nested paths (`metadata.nested.a`), array-contains (`metadata.tags`), `aliases.0`, `$and`/`$or`/`$nor`, unknown-field/unknown-dotted guards, and the exact report case (`{"metadata.size": 720}` no longer matches a `size: None` doc) all verified against `:memory:` buckets.

## Migration Guide

### Upgrading from v1.16.1 to v1.16.2

1. **Seamless Drop-In Replacement:** No APIs or signatures changed.
2. **Behavior Fix — Dotted Metadata Filters:** queries like `find({"metadata.size": 720})` that previously returned the whole bucket now filter correctly. If application code worked around this (e.g. narrowing by `filename` and matching `metadata` in Python, as micronote.pub's `get_file` does), the workarounds can stay — results are identical — or be removed.
3. **Behavior Fix — Unknown Filters:** unknown top-level fields, dotted paths on scalar columns (e.g. `filename.foo`), and unsupported operators now return `[]` instead of the whole bucket. Code relying on the old match-everything behavior should be updated.
4. **Behavior Fix — `fs.chunks.find()`:** now returns chunk dicts (`_id`, `files_id`, `n`, `data`) instead of `GridOut` files. Code reading `.filename` off chunks results should read chunk keys instead.
5. **No Data Migration:** storage format is unchanged; the fixes are evaluation-only.
