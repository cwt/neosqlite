# NeoSQLite v1.15.0 Release Notes

## TL;DR

NeoSQLite v1.15.0 is a **major correctness and parity release** resolving all 86 findings from a deep code audit, alongside 16 new SQL-tier expression converters, Tier-1 `$group` activation, a comprehensive module restructuring, and full body-level type checking.

**Key Highlights:**
1. **Translation Cache Correctness** — Cache keys now include literal values; hits return exact stored parameters. Fixes silently wrong results on repeated aggregation pipelines (e.g., descending sort served from an ascending cached template).
2. **MongoDB Null Semantics Aligned** — `{f: null}` matches null-or-missing fields, `$ne` matches absent fields, across find(), SQL translation tiers, and expression evaluators.
3. **GridFS Data Integrity** — `delete_by_name()` removes chunks; unique `(files_id, n)` index prevents racing-writer corruption; aborted uploads roll back instead of committing truncated files.
4. **Tier-1 `$group` Activation** — Fixed the CTE column-contract violation that made every `$group` pipeline silently skip the fast SQL tier.
5. **Typed Rollout** — `check_untyped_defs` enabled project-wide: every function body in `neosqlite/` is now type-checked.

- **Upgrade if you use:** aggregation pipelines with `$group`/`$sort`/`$facet`, translation caching, GridFS, Change Streams, update operators (`$min`/`$max`/`$addToSet`/`$push`), positional `$` updates, upserts, or expression operators.
- **Impact:** Substantially improved MongoDB parity — several operations that returned silently wrong results (or crashed) now behave correctly. See the [Migration Guide](#migration-guide) for the short list of intentional behavior alignments.

---

## Overview

This release consolidates two major work streams:

1. **A deep code audit and systematic remediation** of all 86 identified issues — 11 critical, 18 high, 30 medium, and 17 low severity — spanning correctness, MongoDB-semantics parity, resource leaks, race conditions, and dead code removal.
2. **SQL-tier expansion and structural cleanup**: 16 additional expression operators converted to native SQL, major module splits for maintainability, and elimination of ~700 lines of dead code.

All changes are backward-compatible at the API level. A handful of intentional behavior alignments (documented in the Migration Guide) replace silently incorrect results with MongoDB-correct ones.

## Critical Correctness Fixes

### Translation Cache: Literal-Aware Keys & Exact Parameters

Cache keys previously replaced literal values with `?`, while sort directions and other literals were baked into cached SQL templates. Cache hits then re-derived parameters through an independent walk that disagreed with builder emission order — serving ascending results for a descending sort and corrupting multi-`$match` pipelines on their second execution. Keys now canonicalize the full pipeline content (type-tagged so `1`, `True`, `1.0`, and `"1"` stay distinct), and hits return exact stored parameters.

### Null Semantics Across Tiers

- `{f: null}` and `{$eq: null}` compiled to `= NULL` (never true). Now emit `IS NULL`, matching MongoDB's "null matches null-or-missing."
- `$ne` compiled to `!= ?`, dropping rows where the field was absent. Now emits `IS NOT ?`.
- Expression-level `$eq` between two missing fields is now true in both tiers.

### GridFS Integrity

- `delete_by_name()` selected logical `_id`s to match integer chunk keys, orphaning every chunk. It now selects the internal `id` column.
- New `UNIQUE(files_id, n)` index prevents racing writers from interleaving duplicate chunks (which reads resolved arbitrarily, garbling content).
- Abandoned context-manager uploads now **abort**: partial chunks and file rows are deleted rather than committed as truncated-but-valid files.
- Missing or unfinalized chunks raise `CorruptGridFile` instead of `NoFile` / raw `TypeError`.

### Transaction & Update Safety

- Nested `Connection.transaction()` is refused before any state change; previously the failed inner `BEGIN` triggered a rollback that destroyed the outer transaction's pending work.
- `update_many()` validates `$inc`/`$mul` targets like `update_one()`, raising `MalformedQueryException` instead of silently coercing string fields to numbers via SQLite arithmetic.
- Positional `$` updates resolve the matched element through the full query path (dotted and nested filters included) and refuse to write when the query constrains nothing on the target array — no more silent element-0 corruption.
- Upsert base documents are built from equality predicates only; operator dicts are no longer stored as literal data.

## MongoDB Parity Alignment

### Aggregation Pipeline

- **Tier-1 `$group` activated**: stage builders now honor the `(id, _id, data)` CTE contract, so `$group` pipelines execute in the fast SQL tier instead of always falling back.
- **Window default frame**: `$setWindowFields` without an explicit window spans the entire partition (both tiers), matching MongoDB — not running totals.
- **`$text` respects sibling filters**: FTS results are AND-ed with remaining query conditions instead of replacing them.
- **Tier-2 composition**: consecutive `$skip`/`$limit` stages compose sequentially; `$unionWith` with a sub-pipeline falls back rather than unioning everything.
- **`$first`/`$last`** work via a ranked CTE; constant-key groups on empty input return zero documents; `$densify` preserves originals; `$lookup`+pipeline handles multiple matches.

### Query Operators & Expressions

- Boolean-emitting operators (`$isArray`, `$regexMatch`, `$toBool`, `$isNumber`) return integers, fixing composite predicates like `{"$and": [{"$isArray": ...}, ...]}`.
- Arithmetic aligned with MongoDB: `$divide` returns doubles, `$mod` uses C sign convention, `$round` rounds half-to-even.
- Date operators: dynamic amounts convert units correctly (`year` adds years, not months); `$dateDiff` counts boundary crossings; `$dateFromString` applies timezone offsets.
- String operators: byte-accurate `$substrBytes`; empty-find `$replaceAll` returns input unchanged; single-literal `$toLower`/`$toUpper` accepted.
- Plain equality gains array-containment semantics; `$regex` never matches missing fields; numeric `$type` aliases exclude booleans; `$elemMatch` resolves dotted paths and re-raises malformed sub-query errors.

### Query & Cursor Behavior

- Python-tier sorts use BSON type ordering — mixed/missing keys no longer raise `TypeError`.
- `Cursor.alive` correctly reports exhaustion; `distinct()` flattens arrays and dedupes documents; `$elemMatch`/`$contains` resolve dot-notation.
- Raw batch queries order by rowid by default, preventing skipped/duplicated documents across OFFSET pages.
- `parse_json_path("_id")` callers reference the dedicated `_id` column directly.

## Resource, Lifecycle & Leak Fixes

- Temp tables for `$facet`, `$text`, and tier-2 `$expr` are owned by the pipeline context — leaks eliminated on both success and failure paths.
- Change Streams: triggers are reference-counted per collection, consumption is watermark-based (concurrent streams can no longer steal each other's events), and the last close purges events — bounding table growth.
- Savepoint names are UUID-derived in sessions and bulk executors, eliminating id-reuse collisions and interleaved-executor stack corruption.
- `drop_collection()` evicts cache entries and drops FTS5 objects; renames check `sqlite_master` and carry FTS tables along; bounded caches replace unbounded global dicts.
- Expected tier fallbacks log at WARNING without tracebacks, keeping real failures visible.

---

## Performance Improvements

- Eliminated the N+1 document-loading storm: raw-batch loads issue 2 statements per 5 documents instead of 16.
- Tier-3 `$lookup` builds one hash index over the foreign collection instead of rescanning per document (O(N+M) vs O(N×M)).
- GridFS: chunk inserts batched inside one transaction, file IDs cached per stream, write buffer consumes via offset (no quadratic memmove), PRAGMA introspection cached.
- `$to_list(length)` bounds SQLite work via `itertools.islice`; `$facet` result rows insert via `executemany`.

## Developer Experience

- **Typed rollout**: `check_untyped_defs = True` — every function body in `neosqlite/` is type-checked even without annotations; demo scripts and test suites excluded from gating.
- **~700 lines of dead code removed**: stub stage builders, duplicate dispatch arms, the dead multi-`$unwind` builder chain, production-dead `EnhancedDateTimeQueryProcessor`, unused constants/helpers, and broken `__all__` exports fixed.
- **API contracts honored**: `create_index(sparse=True)` builds partial indexes; `ExprTempTableManager(filter_expr=...)` applies its filter; `CorruptGridFile` is actually raised.
- **Migration safety**: auto-vacuum migration snapshots via the sqlite backup API (consistent, no torn copies), escapes `VACUUM INTO` paths, and honors `target_journal_mode`.

## Migration Guide

### Upgrading from v1.14.15

The API surface is unchanged, but this release **replaces silently incorrect behavior with MongoDB-correct behavior**. Most users see only fixes. Review these alignments if your code depended on the old lenient paths:

1. **Null equality**: `find({"f": None})` now matches documents where `f` is null *or absent* (previously matched nothing).
2. **`update_many` validation**: `$inc`/`$mul` on non-numeric fields raises `MalformedQueryException` instead of overwriting values with garbage.
3. **Positional `$`**: requires the query to constrain the array; unmatched filters refuse to update instead of writing element 0.
4. **Upserts**: base documents include only equality predicates — operator dicts are no longer persisted as data.
5. **Sparse indexes**: `create_index(..., sparse=True)` now builds a partial index (documents missing the field are excluded).
6. **Nested transactions**: `with conn.transaction():` inside another raises `OperationalError` before doing any work (outer work survives).
7. **Strict `_id`**: string `_id` values are no longer coerced to integers; range queries fall back to Python for correct cross-type ordering.
8. **Repeat-query correctness**: aggregation results that were previously served stale from the translation cache will now differ — correctly.

**Recommended for all users**, especially those running aggregation pipelines with caching enabled, GridFS in multi-threaded writers, Change Streams with multiple consumers, or applications performing positional array updates.
