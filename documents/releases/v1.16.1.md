# NeoSQLite v1.16.1 Release Notes

## TL;DR

NeoSQLite v1.16.1 is a **correctness patch**. `ObjectId` gains Python-level ordering (`__lt__`/`__le__`/`__gt__`/`__ge__` over the 12-byte big-endian value), which fixes `_id` range queries (`$gt`, `$gte`, `$lt`, `$lte`) silently returning nothing in both query tiers, and routes `ObjectId` filter values away from raw SQL parameter binding, fixing the `count_documents` crash. Cursor pagination via `{_id: {$gt: lastSeenId}}` now works verbatim. Fully backward compatible.

**Key Highlights:**
1. **ObjectId Ordering** — 12-byte BSON byte order with `NotImplemented` (hence `TypeError`) for non-`ObjectId` comparisons, mirroring `bson`.
2. **`_id` Range Queries Fixed** — `find()` and `count_documents()` with ObjectId ranges return correct, ObjectId-only results on mixed-type `_id` columns.
3. **Cursor Pagination Unblocked** — the standard `sort(_id)` + `{_id: {$gt: cursor}}` + `limit(n)` pattern works on both tiers.

---

## Detailed Changes

### Core `neosqlite` Engine

* **ObjectId ordering (`neosqlite/objectid.py`):**
  Added `__lt__`, `__le__`, `__gt__`, `__ge__` comparing the raw 12-byte value, so `sorted()` and the Python query tier order ObjectIds instead of raising `TypeError` (which the operator layer swallowed into no-match).
* **`_id` range fallback (`neosqlite/collection/sql_translator_unified.py`):**
  Filter values containing an `ObjectId` now fall back to Python evaluation instead of being bound as raw SQL parameters. This mirrors the existing `_id` range fallback in the query-helper builder. SQL stays bypassed for `_id` ranges by design: the mixed `INTEGER`/`TEXT` `_id` column cannot express BSON cross-type rules in SQL. Sorting on `_id` was already correct via the hex `TEXT` column and is unchanged.

### Tests

* **New `tests/test_objectid_ordering.py` (14 tests, both tiers):**
  byte-order conformance, `TypeError` parity with `bson`, all four range operators for `find`/`count_documents`, ObjectId-only matching on mixed-type `_id` columns, equality/`$in` regression coverage, and a `newer_than` cursor-pagination test.

## Migration Guide

### Upgrading from v1.16.0 to v1.16.1

1. **Seamless Drop-In Replacement:** No APIs or signatures changed.
2. **Behavior Fix — `_id` Ranges:** queries like `find({"_id": {"$lt": oid}})` that previously returned `[]`, and `count_documents()` calls that raised `ProgrammingError`, now return correct results. If application code worked around the empty results (e.g. client-side filtering), the workarounds can stay — results are identical — or be removed.
3. **No Data Migration:** storage format is unchanged; the fix is evaluation-only.
