# NeoSQLite v1.16.0 Release Notes

## TL;DR

NeoSQLite v1.16.0 is a **feature release** completing the `micronote.pub` migration backlog: modern PyMongo call-shape parity, MongoDB-compatible TTL index expiry, and change-stream hardening that enables SQLite-backed job queues as a Celery replacement. All additions are backward compatible; existing behavior is unchanged unless the new options are used.

**Key Highlights:**
1. **PyMongo Modern Parity** — `find()` accepts `limit`/`skip`/`sort` kwargs; `create_index()` accepts `expireAfterSeconds`, `name`, and extra options; new `Connection.get_database()` / `drop_database()` compat helpers.
2. **TTL Index Expiry** — `expireAfterSeconds` declaration with `purge_expired()`, best-effort auto-purge on `find`/`find_one`, and an opt-in `ttl_sweep_interval_s` background sweeper.
3. **Change-Stream Hardening** — `resume_after` / `start_after` resume tokens with a `resume_token` property, library-side `$match` pipeline filtering, bounded resume history, and a documented drain-then-tail job-queue recipe (`examples/watch_job_queue.py`).

## Detailed Changes

### PyMongo Modern API Parity

* **`find()` option kwargs:**
  `find(filter, limit=N, skip=M, sort=...)` now applies the options to the returned `Cursor` (`0`/`None` limit means no limit). Sort accepts a list of `(key, direction)` tuples, a dict, a single `(key, direction)` tuple, or a field name. Unknown extra kwargs are accepted and ignored for forward compatibility. GridFS-system-collection reads are unaffected.
* **Index declaration options:**
  `create_index()` / `create_indexes()` (including via `IndexModel`) accept `expireAfterSeconds` (validated `0`–`2147483647`, stored in `_neosqlite_ttl_indexes` metadata, visible in `index_information()`), plus `name` and other extra options for compatibility. `create_index()` now returns the generated index name. Compound, FTS, and datetime-field TTL combinations raise `ValueError`. TTL metadata is cleaned on index/collection drops and carried over renames.
* **Database helpers:**
  `Connection.get_database(name=None)` returns `self` (single-file DB), and `Connection.drop_database(name=None)` drops all tables as a test/debug helper. Defining real methods also fixes attribute access previously trapped by the collection-name `__getattr__` fallback.

### TTL Index and Document Expiry

* **Declaration** is covered above; expiry itself is new:
  `Collection.purge_expired(now=None)` deletes documents where `now >= field_value + expireAfterSeconds` (UTC datetimes and numeric epoch seconds both supported; explicit `now` keeps tests sleep-free) and returns the deleted count.
* **Lazy expiry:** `find()` / `find_one()` on a TTL collection auto-purge best-effort before reading; reads never fail because of expiry.
* **Background sweeper (opt-in):** `Connection(path, ttl_sweep_interval_s=60)` runs a daemon thread sweeping all TTL collections each tick through a short-lived helper connection (the main `sqlite3` handle is never shared across threads). `:memory:` databases skip the thread; `sweep_ttl_once()` runs a manual pass.
* **Semantics note:** deletions are plain deletes firing normal `watch()` events. MongoDB guarantees ~60s background granularity; NeoSQLite guarantees lazy (on next read) plus sweeper-tick granularity. See [TTL Indexes and Document Expiry](../ttl-indexes.md).

### Change Streams for Job Queues

* **Resume tokens:** `watch(resume_after=token)` / `start_after=token` (tokens are `change["_id"]`, i.e. `{"id": N}`) replay changelog rows after the token instead of starting from "now". The two options are mutually exclusive; malformed tokens raise `ValueError`. The new `resume_token` property returns the last returned event's token (`None` before the first event).
* **Pipeline filtering:** library-side `$match` evaluation (equality plus `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$in`, `$nin`, `$exists` on dotted paths such as `operationType`, `ns.coll`, `fullDocument.status`, plus top-level `$and`/`$or`/`$nor`). Other stages are accepted and ignored. Filtering on `fullDocument.*` requires `full_document="updateLookup"`.
* **Bounded resume history:** the last close drops triggers but retains the most recent changelog rows (currently 1000 per collection) so a later resume token can replay crash-restart gaps. Tokens older than the window replay from the oldest retained row.
* **Recipe:** documented drain-then-tail worker pattern (startup `find()` drain for pre-open/stream-less windows, then `watch()` tail; retry bookkeeping stays app-side) in [Change Streams with watch()](../watch.md), with runnable `examples/watch_job_queue.py`.

## Migration Guide

### Upgrading from v1.15.2 to v1.16.0

1. **Seamless Drop-In Replacement:** No existing APIs or signatures were broken. `create_index()` additionally returns the index name (previously `None`); callers ignoring the return value are unaffected.
2. **TTL auto-purge:** collections with `expireAfterSeconds` indexes now delete expired documents on `find`/`find_one` and via the sweeper when enabled. Declare TTL only on fields you truly want expired.
3. **Change streams:** resume and `$match` filtering are opt-in. The last close now retains bounded changelog history instead of purging everything; plan capacity accordingly (1000 rows per watched collection).
4. **New databases objects:** `_neosqlite_ttl_indexes` metadata table is created on demand alongside the existing `_neosqlite_changestream` table.
