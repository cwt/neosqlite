# NeoSQLite v1.17.4 Release Notes

## TL;DR

NeoSQLite v1.17.4 is a **critical correctness and SQLite engine compatibility release**. It resolves a major silent data type regression introduced by SQLite's internal subtype handling changes in SQLite **≥ 3.54.0** (including SQLite 3.54.1 on macOS / Homebrew), where scalar subqueries dropped the internal `'J'` JSON subtype across subquery boundaries. This previously caused `json_set()`, `jsonb_set()`, and `json_object()` to serialize subquery array and object results into escaped JSON string literals (e.g. `'"[1, 2, 3]"'`) instead of native JSON arrays or objects.

By wrapping all JSON-producing scalar subqueries with an outer `json((SELECT ...))` expression, NeoSQLite restores the `'J'` subtype uniformly across modern SQLite (≥ 3.54) while maintaining full backward compatibility with older SQLite versions (≤ 3.53, e.g. Fedora 45). Additionally, this release eliminates unclosed connection `ResourceWarning` leaks and aligns NX-27017 wire protocol dependencies. Fully backward compatible.

**Key Highlights:**
1. **SQLite ≥ 3.54 Scalar Subquery Subtype Fix** — Wrapped all scalar subqueries producing JSON in `json((SELECT ...))`, guaranteeing that enclosing functions (`json_set`, `jsonb_set`, `json_object`) recognize subquery outputs as structured JSON rather than plain text strings on SQLite ≥ 3.54.
2. **Hardened Array Updates** — Fixed `$push` (with `$position` and `$slice`), `$pull`, and `$pullAll` update SQL clauses so updated documents retain proper JSON array structures in both TEXT and JSONB modes.
3. **Hardened Aggregation & `$expr` Array Converters** — Updated SQL converters for `$slice`, `$firstN`, `$lastN`, `$sortArray`, `$filter`, `$map`, `$maxN`, `$minN`, `$setIntersection`, `$setUnion`, `$setDifference`, and `$objectToArray` to prevent stringification of nested arrays and objects.
4. **Clean Resource Management** — Resolved unclosed SQLite connection leaks and associated Python `ResourceWarning` notices.
5. **Cross-Engine Verification** — Verified 100% test pass on modern SQLite (macOS, SQLite 3.54.1 / Python 3.14) and older SQLite (Fedora 45 Apple container, SQLite 3.53.4 / Python 3.15). All 3,034 tests in `neosqlite` pass with **80.70%** line coverage; all 180 tests in `nx_27017` pass.

## Detailed Changes

### SQLite ≥ 3.54 Subquery Subtype Propagation

* **Root Cause & Mechanism:**
  * In SQLite **≤ 3.53.4**, scalar subqueries returning JSON functions (such as `(SELECT json_group_array(...) ...)`) propagated SQLite's internal JSON subtype (`'J'`) across the subquery boundary.
  * In SQLite **≥ 3.54.0**, scalar subquery boundaries `(SELECT ...)` clear all value subtypes upon returning to the outer query context. Consequently, enclosing JSON functions saw subtype `0` (plain text) and escaped the result as a string literal.
  * Wrapping the subquery with `json((SELECT ...))` evaluates the subquery first, and then the outer `json()` function assigns the `'J'` subtype in the outer query context, ensuring proper handling across all SQLite versions.

* **Update Clause Builders:**
  * `neosqlite/collection/query_helper/_sql_updates.py`:
    * [`_build_push_position_slice_clause`](file:///Users/cwt/Projects/neosqlite/neosqlite/collection/query_helper/_sql_updates.py#L318): Wrapped `(SELECT json_group_array(value) FROM ({final_select}))` with `json(...)`.
    * `$pull` & `$pullAll`: Wrapped subqueries in both `_build_bulk_update_clauses` and `_build_sql_update_clause` with `json(...)`.

* **Array & Object SQL Converters:**
  * `neosqlite/collection/expr_evaluator/sql_converters/array.py`:
    * Enclosed subqueries in `json((SELECT ...))` for `$slice`, `$firstN`, `$lastN`, `$sortArray`, `$filter`, `$map`, and `_convert_extreme_n` (`$maxN` / `$minN`).
    * Fixed an indentation bug in `$slice` where literal skip offsets were improperly scoped under the validation error branch.
  * `neosqlite/collection/expr_evaluator/sql_converters/set.py`:
    * Enclosed outer subqueries in `json(...)` for `$setIntersection`, `$setUnion`, and `$setDifference`.
  * `neosqlite/collection/expr_evaluator/sql_converters/object.py`:
    * Enclosed `$objectToArray` subquery in `json(...)`.

### Resource Management & Typing

* Eliminated unclosed SQLite connection leaks and silenced associated `ResourceWarning` diagnostic messages.
* Corrected internal type hints across query helper and expression evaluation paths.

### Package & Dependency Alignment

* Updated `pyproject.toml` version to `1.17.4`.
* Updated `packages/nx_27017/pyproject.toml` dependency constraint to `neosqlite = "^1.17.4"`.
