# NeoSQLite v1.18.1 Release Notes

## TL;DR

NeoSQLite v1.18.1 is a **cumulative correctness, SQL-tier parity, SQLite 3.26-3.54 compatibility, and runtime modernization release**. It rolls up every change since the v1.17.4 tag — kill-switch completeness, SQL Tier 1/2 correctness, expanded Tier-3 promotion, CRUD/write parity, coverage-driven bug fixes, SQLite 3.26–3.54 compatibility and `_id BLOB` migration, and Python 3.12 modernization — and raises the minimum supported Python version to **3.12**.

> Note: v1.18.0 was tagged but never published on PyPI. v1.18.1 supersedes it and is the first published release in the 1.18.x line. It contains everything planned for v1.18.0 plus all post-tag regression and AlmaLinux 8 verification fixes.

This release is **not backward compatible for Python 3.10/3.11 users**. Applications still running those interpreters should stay on NeoSQLite v1.17.4.

## Breaking Changes

- **Minimum Python is now 3.12** (`>=3.12,<3.16`). Python 3.10 and 3.11 are no longer supported.
- **`nx-27017` v0.9.0 also requires Python 3.12+** and remains compatible with NeoSQLite v1.17.4+, tested with v1.18.1. The `nx27017` extras accept nx-27017 0.8.x or 0.9.x.
- **`serverStatus` no longer returns `python_sqlite_version`.** The underlying `sqlite3.version` attribute was deprecated in Python 3.12 and removed in Python 3.14. The standard `version` field still reports `sqlite3.sqlite_version`.

## Cumulative Fixes Since v1.17.4

### Kill-Switch Completeness

- `NEOSQLITE_FORCE_FALLBACK` now initializes the global kill switch from the environment.
- Queries, cursors, CRUD, `find_one_and_*`, counts, distinct, and aggregation paths now honor the global kill switch and fall back to Python Tier 3 as the correctness reference.
- Added pure-Python `$facet` and `$collStats` handling plus `{"$meta": "textScore"}` sorting under kill-switch mode.
- Guarded the `$count` shortcut and `explain_aggregation` Tier-2 reporting.
- Preserved GridFS IO as SQL-only while decoupling GridFS file updates from the general match translator.
- Added `tests/test_kill_switch_completeness.py` covering environment initialization, parity across operations, GridFS SQL-only behavior, and SQL trace verification.

### SQL Tier 1/2 Correctness and Parity (Section 1)

- Eliminated accidental Tier-3 fallbacks and hardened Tier-1/Tier-2 parity.
- Expanded SQL translation and query building for `$match` including logical operators, field-level `$not`, `$elemMatch`, regex with `$options`, `$in`, `$nin`, and BSON JSON type guards.
- Added date comparison normalization for datetime literals and date-producing SQL expressions.
- Added ObjectId/Binary fallback guards where SQL scalar comparison would change BSON semantics.
- Fixed `$project` `_id` inclusion defaults, `$group` key-expression handling, `$unwind`, `$addFields`, and changelog JSON normalization for JSONB writes.
- Added Tier-2 semantic hazard checks and a cached match translator.
- Added `tests/test_section1_tier_routing.py`.

### SQL Tier Promotion and Write Parity (Section 2)

- Added nested operand support for `$log` / `$sigmoid` and expanded SQL converter coverage across array, conditional, date, math/trig, and string operators.
- Expanded Tier-1/Tier-2 SQL coverage for `$facet`, `$setWindowFields`, `$fill`, `$densify`, `$graphLookup`, `$redact` (`$$KEEP` / `$$PRUNE`), `$out`, and `$merge`.
- Aligned `$densify` bounds and output semantics across Tier 1, Tier 2, and Python Tier 3; avoided spurious `_id: 0` injection in Tier-2 `$facet`; and auto-initialized missing `$out` / `$merge` target collections.
- Compiled `$type` and `$jsonSchema` predicates to SQL Tier 1 with Python parity.
- Added SQL projection pushdown and boolean preservation, fixed `INDEXED BY` `.hint()` handling, qualified Tier-2 `$expr` ORDER BY columns, and removed a spurious Tier-1 notification in the `DateTimeQueryProcessor` Python fallback.
- Added the unified `_build_set_data_expression` compiler covering `$set` (including `$[]` and `$[id]` arrayFilters), `$unset`, `$inc`, `$mul`, `$min`, `$max`, `$bit`, `$currentDate`, `$rename`, `$pop`, `$push`, `$addToSet`, dotted/conditional `$pull`, `$pullAll`, and `$setOnInsert`.
- Upgraded `update_one` to fetch-free SQL, `update_many` to single-statement set-based SQL, and `find_one_and_update` / `find_one_and_replace` to `RETURNING` SQL while preserving CHECK constraints, `$inc`/`$mul` validation, and kill-switch parity.
- Added `tests/test_section2_tier_routing.py` and updated tier assertions across aggregation, date, and graph-lookup tests.

### Coverage-Driven Bug Fixes

- Raised targeted coverage for type converters, operators lookup, the Python aggregation engine, and SQL updates, bringing overall coverage to **83.64%** on Python 3.14.10 / SQLite 3.54.1.
- Fixed ObjectId parameter sanitization, correlated subquery SQL syntax and column qualification, and local `_id` extraction in `operators_lookup`.
- Fixed target collection resolution for `$merge` / `$out` and excluded `_id` from `whenMatched="replace"` `$set` payloads.
- Fell back to Python in `_build_set_data_expression` when updating `_id` directly.
- Fixed post-tag SQL/Python tier regressions across `$bucket`/`$bucketAuto` (`array_fields` JSON wrapping and `$push`/`$addToSet`/`$min`/`$max` in Tier 3), `$group` (`_id` JSON subtype preservation with `json_valid(_id, 4)` guard), array containment scalar element guards, `$jsonSchema` scalar/type guards, `$addFields` Stage-0 `root_data` referencing, `$project` dotted field paths and `$$ROOT`/`$$CURRENT` handling, `$lookup` (`preserve_root`, `NULL` array coalescing, and non-JSONB `json_set`), `$setWindowFields` dict `partitionBy` and window frame fallback guards, `$graphLookup` CTE registration order, `$fill` `partitionByFields` and composite `partitionBy`, `$redact` expression operand evaluation, and SQL `$min`/`$max`/`$rename` update edge cases.

### SQLite 3.26–3.54 Compatibility & Schema Migration

- Switched newly created collections to `_id BLOB` column affinity to preserve `int`, `float`, `str`, `bytes`, and `ObjectId` `_id` types on non-JSONB SQLite, and added type-aware `_id` fallback resolution across CRUD, cursors, raw batches, and temp-table `$lookup`.
- Added the `neosqlite-migration` CLI tool to migrate legacy `_id TEXT` collections to `_id BLOB` in a new database copy while preserving indexes and triggers.
- Added SQLite 3.26 (AlmaLinux/RHEL 8) compatibility fallbacks for `VACUUM INTO`, aggregate `FILTER`, JSON `[#]` negative/relative indexing (`_supports_relative_json_indexing`), `$arrayElemAt` / `$last` negative indexing without ephemeral sorter subtype loss, numeric `RANGE` window frames, reduced nested positional update SQL parser depth, and SQLite 3.35+ math functions.
- Centralized JSONB capability detection for SQLite 3.45–3.50 and preserved JSON subtypes across SQLite 3.54 subqueries and temporary tables.

### Tooling and Dependencies

- Refreshed dependencies and regenerated both lock files, dropping vulnerable `dnspython 2.8.0` and `soupsieve 2.10` in favor of `dnspython 2.9.2` and `soupsieve 4.1`.
- Updated helper scripts to run Python, pip, and nx-27017 through `poetry run`, and to prefer Apple's `container` CLI on macOS before podman/docker.
- Updated Python classifiers, mypy, Read the Docs, tox, and README support metadata for Python 3.12–3.15.

## Python 3.12 Runtime and Language Modernization

- Native `datetime.fromisoformat()` parsing of trailing uppercase `Z`.
- `datetime.UTC` replaces `timezone.utc` throughout the library.
- `itertools.batched()` for batch processing in raw cursors and aggregation.
- `math.sumprod()` for `$covariancePop` / `$covarianceSamp`.
- `asyncio.run(..., loop_factory=uvloop.new_event_loop)` without mutating the global event-loop policy.
- `typing.Self` across fluent builders, clones, context managers, and classmethod constructors.
- `@typing.override` on the custom JSON encoder.
- PEP 695 `type` alias for the tier-change callback.
- PEP 701 f-string quote reuse where it improves the generated SQL and path expressions.
- `@dataclass(slots=True)` for hot value objects.
- `itertools.pairwise()` for adjacent-boundary aggregation loops.
- `str.removeprefix()`, `yield from`, comprehension/list-extend/dict-update cleanups, and removal of stale UTF-8 coding headers.

## Hardening and Cleanup

- Added a persistent `[tool.ruff] target-version = "py312"` configuration and updated the lint helper to enforce `UP`/`FURB` across the repository and `PERF` on shipped library code.
- Fixed the remaining `PERF403` and `FURB122` findings.
- Hoisted remaining hot-path function-local standard-library imports while preserving intentional local imports for monkeypatching, optional platform modules, and the stdlib-vs-pysqlite3 version report.
- Migrated tests, examples, and helper scripts to Python 3.12 idioms.
- Replaced the blanket project `DeprecationWarning` suppression with targeted `error` filters for `neosqlite` and `sqlite3`.
- Kept `from __future__ import annotations` where it still protects `TYPE_CHECKING`-only imports.

## Packaging Fixes

- `neosqlite[nx27017]` and `neosqlite[nx27017-speed]` now declare `pymongo` directly.
- `nx-27017[speed]` now declares `uvloop`.
- `pysqlite3-binary` is gated to Linux x86_64 with Python `>=3.12,<3.15` (`sys_platform == 'linux' and platform_machine == 'x86_64'`), matching upstream `manylinux_2_17_x86_64` wheels for cp312–cp314 in `pysqlite3-binary 0.5.4.post2`. `neosqlite[jsonb]` therefore remains installable on Python 3.15, macOS, Windows, and ARM, where the extra installs no additional driver and the standard library SQLite is used.

## Verification

- `neosqlite`: **3,122 passed** (83.64% coverage) on macOS Python 3.14.10 with SQLite 3.54.1; **3,099 passed, 23 skipped** (80.98% coverage) on AlmaLinux 8 with Python 3.12.15 and stdlib SQLite 3.26.0.
- `nx-27017`: **180 passed, 1 skipped** on both macOS (Python 3.14.10) and AlmaLinux 8 (Python 3.12.15).
- New tier-routing, kill-switch completeness, and coverage suites are included in the totals above.
- `mypy`, `black`, and the repository-wide Ruff gates are clean.
- Both wheels verify `Requires-Python: >=3.12,<3.16` and the corrected optional-dependency metadata.

## Upgrading

```bash
python3.12 -m pip install --upgrade "neosqlite==1.18.1"
python3.12 -m pip install --upgrade "nx-27017==0.9.0"
```

If you use the `jsonb` extra outside Linux x86_64 with Python 3.12–3.14, no extra driver is installed; the standard library SQLite is used.
